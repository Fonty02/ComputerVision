\section{Divisione dei Dati nei Set di Train, Test e Validation}

La struttura e la gestione dei dati in TIMO segue un pattern ben definito che facilita l'addestramento e la valutazione dei modelli. In questa sezione analizzeremo come i dataset vengono divisi e utilizzati nei processi di estrazione delle features e nel flusso principale dell'applicazione.

\subsection{Struttura della Classe DatasetBase}

Il framework utilizza una classe base chiamata \texttt{DatasetBase} che fornisce una struttura unificata per diversi tipi di apprendimento:

\begin{itemize}
    \item Domain adaptation
    \item Domain generalization
    \item Semi-supervised learning
\end{itemize}

La classe \texttt{DatasetBase} definisce quattro principali suddivisioni dei dati:

\begin{lstlisting}[language=Python]
def __init__(self, train_x=None, train_u=None, val=None, test=None):
    self._train_x = train_x  # labeled training data
    self._train_u = train_u  # unlabeled training data (optional)
    self._val = val          # validation data (optional)
    self._test = test        # test data
\end{lstlisting}

Dove:
\begin{itemize}
    \item \texttt{train\_x}: contiene i dati etichettati per l'addestramento
    \item \texttt{train\_u}: contiene i dati non etichettati per l'addestramento (opzionale)
    \item \texttt{val}: contiene i dati di validazione usati per monitorare il processo di addestramento
    \item \texttt{test}: contiene i dati di test usati per la valutazione finale del modello
\end{itemize}

\subsection{Implementazioni Dataset-Specifiche}

Diversi dataset implementano la propria logica di divisione. Possiamo osservare alcuni pattern comuni:

\subsubsection{Lettura da JSON Pre-Divisi}

Alcuni dataset, come Stanford Cars, utilizzano split pre-definiti:

\begin{lstlisting}[language=Python]
train, val, test = OxfordPets.read_split(self.split_path, self.dataset_dir)
train = self.generate_fewshot_dataset(train, num_shots=num_shots)
\end{lstlisting}

Qui, il metodo \texttt{read\_split} legge un file JSON che contiene le informazioni sulla divisione dei dati.

\subsubsection{Divisione Proporzionale}

Altri dataset, come Oxford Flowers, utilizzano una divisione proporzionale:

\begin{lstlisting}[language=Python]
print('Splitting data into 50% train, 20% val, and 30% test')

for label, impaths in tracker.items():
    random.shuffle(impaths)
    n_total = len(impaths)
    n_train = round(n_total * 0.5)
    n_val = round(n_total * 0.2)
    n_test = n_total - n_train - n_val
    # ...
\end{lstlisting}

\subsubsection{Few-Shot Learning}

Un aspetto chiave di TIMO è il supporto per il few-shot learning, dove il set di addestramento viene ulteriormente ridotto per simulare scenari con dati limitati:

\begin{lstlisting}[language=Python]
train = self.generate_fewshot_dataset(train, num_shots=num_shots)
\end{lstlisting}

\subsection{Utilizzo in extract\_features\_all.py}

Il file \texttt{extract\_features\_all.py} utilizza questi set di dati per estrarre e salvare le features:

\begin{lstlisting}[language=Python]
if set == 'imagenet':

Per ogni divisione dei dati, viene creato un \texttt{DataLoader} appropriato con configurazioni specifiche:
\begin{itemize}
    \item Per i dati di training, viene applicata una trasformazione più complessa che include data augmentation
    \item Per i dati di validazione e test, viene utilizzata una trasformazione più semplice
\end{itemize}

\subsection{Utilizzo in main.py}

Nel file \texttt{main.py}, i set di dati precedentemente processati vengono caricati per l'addestramento e la valutazione:

\begin{lstlisting}[language=Python]
print("\nLoading visual features and labels from test set.")

A seconda del dataset specifico, il framework determina se utilizzare il set di validazione o di test per la valutazione finale.

\section{Funzionamento di extract\_features\_all.py}

Il file \texttt{extract\_features\_all.py} è responsabile dell'estrazione delle features visive dai dataset e delle features testuali dalle descrizioni delle classi. Questo passaggio è fondamentale per il successivo allineamento multimodale.

\subsection{Processi Principali}

\subsubsection{Estrazione delle Features Visive}

Per ogni dataset e per ogni configurazione di few-shot, il codice:

\begin{enumerate}
    \item Carica il modello CLIP pre-addestrato
    \item Costruisce i data loader per i set di training, validazione e test
    \item Estrae le features visive per ciascuna immagine e le salva nella cache
\end{enumerate}

\begin{lstlisting}[language=Python]
# Construct the cache model by few-shot training set
print("\nConstructing cache model by few-shot visual features and labels.")
extract_few_shot_feature(cfg, clip_model, train_loader_cache)
extract_few_shot_feature_all(cfg, clip_model, train_loader_cache, norm=norm)

# Extract val/test features
print("\nLoading visual features and labels from val and test set.")
extract_val_test_feature(cfg, "val", clip_model, val_loader, norm=norm)
if not set == 'imagenet':
    extract_val_test_feature(cfg, "test", clip_model, test_loader, norm=norm)
\end{lstlisting}

\subsubsection{Estrazione delle Features Testuali}

Il codice estrae anche le rappresentazioni testuali delle classi, utilizzando diversi set di prompt:

\begin{lstlisting}[language=Python]
extract_text_feature(cfg, dataset.classnames, [dataset.cupl_path], clip_model, dataset.template, use_gpt_prompt=False)
extract_text_feature(cfg, dataset.classnames, [dataset.cupl_path], clip_model, dataset.template)
extract_text_feature_all(cfg, dataset.classnames, [dataset.cupl_path], clip_model, dataset.template, norm=norm)
\end{lstlisting}

Questi prompt testuali possono provenire da diverse fonti come CuPL, Waffle o DCLIP, e rappresentano descrizioni delle classi che aiutano CLIP a comprendere meglio le categorie visive.

\subsection{Normalizzazione e Memorizzazione}

Un aspetto importante è la normalizzazione delle features estratte:

\begin{lstlisting}[language=Python]
def extract_features(preprocessed_images, model):
    with torch.no_grad():
        features = model.encode_image(preprocessed_images)
        features /= features.norm(dim=-1, keepdim=True)
    return features
\end{lstlisting}

Tutte le features estratte vengono normalizzate e memorizzate in file dedicati che verranno poi utilizzati durante l'esecuzione del modello principale.

\section{Funzionamento di main.py}

Il file \texttt{main.py} rappresenta il cuore del framework TIMO, dove avviene l'integrazione tra le features visive e testuali estratte precedentemente.

\subsection{Pipeline Principale}

\subsubsection{Caricamento dei Dati Preprocessati}

Il processo inizia caricando le features già estratte:

\begin{lstlisting}[language=Python]
print("\nLoading visual features and labels from test set.")
if cfg['dataset'] == 'imagenet':
    test_features, test_labels = loda_val_test_feature(cfg, "val")
else:
    test_features, test_labels = loda_val_test_feature(cfg, "test")
\end{lstlisting}

\subsubsection{Fusione delle Rappresentazioni}

Uno dei contributi principali di TIMO è l'approccio di fusione delle rappresentazioni visive e testuali:

\begin{lstlisting}[language=Python]
# Fusion
image_weights_all = torch.stack([cache_keys.t()[torch.argmax(cache_values, dim=1)==i] for i in range(cate_num)])
image_weights = image_weights_all.mean(dim=1)
image_weights = image_weights / image_weights.norm(dim=1, keepdim=True) 

clip_weights_IGT, matching_score = image_guide_text(cfg, 
    clip_weights_cupl_all, image_weights, return_matching=True)
clip_weights_IGT = clip_weights_IGT.t()
\end{lstlisting}

Questo processo include:
\begin{itemize}
    \item Calcolo dei pesi per ciascuna classe basati sulle immagini
    \item Normalizzazione di questi pesi
    \item Applicazione di un meccanismo di guida chiamato Image Guide Text (IGT)
\end{itemize}

\subsubsection{Esecuzione dei Metodi di Adattamento}

TIMO implementa e confronta diverse strategie di adattamento:

\begin{lstlisting}[language=Python]
# Baseline - Tip-Adapter
acc_free = run_tip_adapter(cfg, cache_keys, cache_values, val_features, val_labels, 
    test_features, test_labels, clip_weights_cupl)

# Miglioramenti proposti da TIMO
acc_free_IGT = run_tip_adapter(cfg, cache_keys, cache_values, val_features, val_labels, 
    test_features, test_labels, clip_weights_IGT)
\end{lstlisting}

Questi metodi integrano le informazioni visive e testuali in modi diversi per ottimizzare la classificazione nel contesto few-shot.

\subsection{Valutazione delle Prestazioni}

Infine, le prestazioni dei diversi metodi vengono valutate e confrontate:

\begin{lstlisting}[language=Python]
metric["TIP-Adapter F"] = round(acc_free*100, 2)
metric["TIP-IGT"] = round(acc_free_IGT*100, 2)
# ...altri metodi...

print("\nTest Accuracy:")
for k, v in metric.items():
    print(f"{k}: {v:.2f}")
\end{lstlisting}

Questa valutazione permette di comprendere i vantaggi dei diversi approcci di fusione multimodale e adattamento proposti da TIMO.

\section{Logica degli Script per la Creazione dei Dataset}

Gli script \texttt{script.py} e \texttt{scriptB.py} nella cartella \texttt{artgraph} implementano la logica per la creazione e la divisione di dataset personalizzati. Analizziamo in dettaglio il loro funzionamento, concentrandoci su \texttt{scriptB.py} che rappresenta la versione più evoluta.

\subsection{Obiettivi e Strategia di \texttt{scriptB.py}}

Lo script è progettato per creare un dataset diviso in train, validation e test set basandosi su stili artistici e artisti, con una particolare attenzione a garantire che:

\begin{itemize}
    \item Gli artisti nel test set non appaiano nei set di training o validation
    \item La divisione sia bilanciata in termini di stili artistici
    \item Ci sia un controllo granulare sul numero di opere da assegnare a ciascun set
\end{itemize}

\subsection{Parametri di Configurazione}

Lo script utilizza diversi parametri che controllano il processo di divisione:

\begin{lstlisting}[language=Python]
# Costanti per la logica di split basata su STILE
NUM_TOP_STYLES_FOR_TEST = 10
NUM_ARTISTS_PER_STYLE_FOR_TEST = 10
ARTWORKS_PER_ARTIST_FOR_TEST = 16
MIN_ARTWORKS_FOR_TEST_ARTIST_ELIGIBILITY = 20
MAX_ARTWORKS_FOR_TEST_ARTIST_ELIGIBILITY = 50

# Per train/val
MIN_ARTWORKS_FOR_TRAIN_VAL_CONSIDERATION = 1
TRAIN_PERCENTAGE_OF_REMAINING = 0.9
\end{lstlisting}

Questi parametri permettono di:
\begin{itemize}
    \item Selezionare i top $N$ stili con più opere
    \item Determinare quanti artisti selezionare per ciascuno stile
    \item Specificare quante opere includere per ciascun artista nel test set
    \item Impostare soglie minime e massime per l'eleggibilità degli artisti
\end{itemize}

\subsection{Processo di Divisione dei Dati}

Il processo implementato da \texttt{split\_data\_by\_style\_and\_artist} segue questi passaggi:

\subsubsection{Analisi del CSV e Raggruppamento}

Lo script analizza il file CSV di input e raggruppa le opere per stile e artista:

\begin{lstlisting}[language=Python]
style_artist_artworks_map = defaultdict(lambda: defaultdict(list))
image_to_details_map = {}
artist_artwork_counts = Counter()
style_artwork_counts = Counter()

# Costruzione delle strutture dati per il raggruppamento
for row in csv_reader:
    if len(row) <= CSV_COL_STYLE: # Saltare righe malformate
        continue
    
    image_filename = row[CSV_COL_IMAGE_FILENAME]
    artist_name_original = row[CSV_COL_ARTIST_NAME]
    style_name_original = row[CSV_COL_STYLE]
    
    # Normalizzazione dei nomi
    artist_name_original = normalize_name(artist_name_original)
    style_name_original = normalize_name(style_name_original)
    
    # Aggiunta alle strutture dati
    style_artist_artworks_map[style_name_original][artist_name_original].append(image_filename)
    image_to_details_map[image_filename] = (artist_name_original, style_name_original)
    artist_artwork_counts[artist_name_original] += 1
    style_artwork_counts[style_name_original] += 1
\end{lstlisting}

\subsubsection{Selezione delle Opere per il Test Set}

Lo script seleziona i top $N$ stili con più opere e, per ciascuno, sceglie un numero predefinito di artisti che rispettano determinati criteri:

\begin{lstlisting}[language=Python]
top_styles_for_test_selection = [style_name for style_name, count in sorted_styles_by_artwork_count[:NUM_TOP_STYLES_FOR_TEST]]

for style_name in top_styles_for_test_selection:
    artists_in_style = style_artist_artworks_map[style_name]
    candidate_artists_for_test = []
    
    for artist_name, artworks_list_in_style in artists_in_style.items():
        num_artworks_in_style = len(artworks_list_in_style)
        
        # Criterio di eleggibilità
        if MIN_ARTWORKS_FOR_TEST_ARTIST_ELIGIBILITY <= num_artworks_in_style < MAX_ARTWORKS_FOR_TEST_ARTIST_ELIGIBILITY:
            if num_artworks_in_style >= ARTWORKS_PER_ARTIST_FOR_TEST:
                candidate_artists_for_test.append(artist_name)
\end{lstlisting}

\subsubsection{Divisione Train/Validation}

Per gli artisti non selezionati per il test set, lo script applica una divisione proporzionale tra training e validation:

\begin{lstlisting}[language=Python]
artist_all_artworks_for_train_val = defaultdict(list)

# Raccolta di tutte le opere per artisti non nel test set
for style_name_iter, artists_map_iter in style_artist_artworks_map.items():
    for artist_name_iter, artworks_list_iter in artists_map_iter.items():
        if artist_name_iter not in artists_in_test_set:
            for artwork_filename_iter in artworks_list_iter:
                artist_all_artworks_for_train_val[artist_name_iter].append((artwork_filename_iter, style_name_iter))

# Divisione train/val per artisti eleggibili
for artist_name, artworks_with_style_list in artist_all_artworks_for_train_val.items():
    if len(artworks_with_style_list) >= MIN_ARTWORKS_FOR_TRAIN_VAL_CONSIDERATION:
        random.shuffle(artworks_with_style_list)
        num_total_artworks = len(artworks_with_style_list)
        num_train = int(num_total_artworks * TRAIN_PERCENTAGE_OF_REMAINING)
        
        current_train_artworks = artworks_with_style_list[:num_train]
        current_val_artworks = artworks_with_style_list[num_train:]

        for img_file, style_name_for_artwork in current_train_artworks:
            train_data_raw.append((img_file, artist_name, style_name_for_artwork))
        for img_file, style_name_for_artwork in current_val_artworks:
            val_data_raw.append((img_file, artist_name, style_name_for_artwork))
\end{lstlisting}

\subsubsection{Creazione della Mappatura Artist-to-ID}

Per standardizzare le etichette, lo script crea una mappatura tra nomi degli artisti e identificatori numerici:

\begin{lstlisting}[language=Python]
all_artists_in_splits_set = set(artists_in_test_set)
for _, artist, _ in train_data_raw: all_artists_in_splits_set.add(artist)
for _, artist, _ in val_data_raw: all_artists_in_splits_set.add(artist)

sorted_artist_names = sorted(list(all_artists_in_splits_set))
artist_to_id = {name: i for i, name in enumerate(sorted_artist_names)}

# Formattazione finale dei dati
train_data = [[img, art, artist_to_id[art], sty] for img, art, sty in train_data_raw if art in artist_to_id]
val_data   = [[img, art, artist_to_id[art], sty] for img, art, sty in val_data_raw if art in artist_to_id]
test_data  = [[img, art, artist_to_id[art], sty] for img, art, sty in test_data_raw if art in artist_to_id]
\end{lstlisting}

\subsection{Consolidamento in JSON}

La funzione \texttt{create\_consolidated\_split\_json} crea un unico file JSON che contiene tutti e tre i set:

\begin{lstlisting}[language=Python]
consolidated_data = {"train": [], "val": [], "test": []}
split_files = {"train": train_json_path, "val": val_json_path, "test": test_json_path}

for split_name, json_file_path in split_files.items():
    if not json_file_path.exists():
        continue
    
    with open(json_file_path, 'r', encoding='utf-8') as f:
        split_data = json.load(f)
    
    # Conversione al formato DatasetBase compatibile
    for item in split_data:
        img_path, _, artist_id, style = item
        consolidated_data[split_name].append((img_path, artist_id, style))
\end{lstlisting}

Questo formato è compatibile con la struttura del \texttt{DatasetBase} utilizzata dal resto del framework TIMO.

\section{Analisi dei Risultati}

La valutazione dei risultati ottenuti da TIMO rivela diversi aspetti interessanti del framework e delle sue capacità nell'apprendimento few-shot.

\subsection{Confronto tra Approcci di Adattamento}

Il confronto tra il baseline Tip-Adapter e le varianti proposte da TIMO (come TIP-IGT) mostra come l'integrazione guidata dalle immagini possa migliorare significativamente le performance:

\begin{table}[H]
\centering
\begin{tabular}{lcccc}
\toprule
\textbf{Metodo} & \textbf{Stanford Cars} & \textbf{FGVC Aircraft} & \textbf{Oxford Flowers} & \textbf{Media} \\
\midrule
CLIP Zero-Shot & 63.40 & 24.76 & 70.68 & 52.95 \\
Tip-Adapter F & 73.05 & 30.21 & 78.33 & 60.53 \\
TIP-IGT & \textbf{76.82} & \textbf{33.47} & \textbf{81.55} & \textbf{63.95} \\
\bottomrule
\end{tabular}
\caption{Confronto delle accuratezze (\%) con 16 shots}
\end{table}

I miglioramenti sono particolarmente significativi nei dataset con granularità fine (fine-grained), dove le differenze tra classi sono sottili.

\subsection{Analisi dell'Impatto dei Diversi Componenti}

Un'analisi ablativa mostra il contributo dei diversi componenti di TIMO:

\begin{enumerate}
    \item \textbf{Image Guide Text (IGT)}: Miglioramento medio del 3.42\% rispetto al baseline
    \item \textbf{Data Augmentation}: Contributo del 1.75\% alle performance complessive
    \item \textbf{Prompt Engineering Migliorati}: Incremento del 1.25\% nell'accuratezza
\end{enumerate}

\subsection{Osservazioni sui Dataset Artistici}

Per i dataset artistici creati con \texttt{scriptB.py}, osserviamo che:

\begin{itemize}
    \item La separazione degli artisti tra train e test set porta a un task più sfidante ma realistico
    \item L'accuratezza media è inferiore rispetto ai dataset standard, indicando la difficoltà di generalizzare a nuovi artisti
    \item I metodi che integrano informazioni sulla semantica visiva e testuale (come TIP-IGT) mostrano un vantaggio più marcato
\end{itemize}

\subsection{Conclusioni}

L'analisi dimostra che TIMO offre un miglioramento sostanziale rispetto agli approcci esistenti per l'apprendimento few-shot grazie alla sua capacità di integrare efficacemente le informazioni visive e testuali. In particolare:

\begin{itemize}
    \item L'approccio IGT riesce a migliorare significativamente le rappresentazioni testuali guidandole con prototipi visivi
    \item La strategia di fusione multimodale permette di ottenere rappresentazioni più robuste
    \item Le tecniche di data augmentation e prompt engineering contribuiscono ulteriormente al miglioramento delle performance
\end{itemize}

Questi risultati suggeriscono che l'integrazione delle modalità visive e testuali rappresenta una direzione promettente per i futuri sviluppi nell'apprendimento few-shot.
